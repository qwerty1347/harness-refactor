# harness-refactor

레거시 코드를 진단하는 Claude Code 하네스.

지정한 파일 **하나**를 읽고 기술부채를 찾아, 항목마다 **근거 / 출처 / 등급**을 붙인 리포트를 만든다.
코드는 고치지 않는다. 설계 근거는 [DESIGN.md](DESIGN.md).

## 실행

```
/refactor app/Http/Controllers/ElasticSearchController.php
```

대상 프로젝트 디렉토리에서 실행한다. 산출물은 CWD 기준.

```
_workspace/
├── 00_input.md              스택 · 런타임 상한 · 근거 목록
└── 01_legacy_analysis.md    진단 리포트
```

> **에이전트 md 를 고치면 세션을 다시 열어야 반영된다.** 디스크가 최신이어도
> 실행 중인 세션은 옛 정의를 쓴다.

## 리포트

5 절 고정 — 대상 / 의존 목록 / 발견 항목 / 의도 불명 / 요약.

| 등급 | 조건 | 뜻 |
|---|---|---|
| 자동 | 설정 파일 · 컨벤션 문서에 **문자 그대로 적힌** 근거가 있다 | 확인 없이 고쳐도 되는 것 |
| 확인 필요 | 그 밖의 전부 | **사람 확인 없이 고치면 안 되는 것** |

419 줄 Laravel 컨트롤러 실행 결과의 요약 절:

```markdown
- 자동: 1건 — F-05
- 확인 필요: 12건 — F-01, F-02, F-03, F-04, F-06, F-07, F-08, F-09, F-10, F-11, F-12, F-13
- 의도 불명: 2건 — L177-206, L340
- 가장 무거운 항목: F-01, F-02, F-13
```

## 범위

- **대상 파일 하나 안에서 끝낸다.** 호출자를 찾지 않고, 의존 파일을 열지 않는다
- 확인 안 한 것은 단정하지 않는다 — "안 쓰인다" 같은 지적은 `파일 밖 확인 필요` 로만
- 정적 분석 도구를 설치하거나 실행하지 않는다
- `_workspace/` 밖에 쓰지 않는다
- `legacy-analyzer` 는 스택을 모른다. 스택별 값은 `00_input.md` 로 들어온다

## 만들면서 틀린 것들

| 증상 | 원인 |
|---|---|
| 진단 시간 두 배 | 리포트를 analyzer 가 반환하고 오케스트레이터가 다시 씀 — 같은 글 두 번 생성 |
| 툴 호출 32 회 / 10 분 | 호출자를 찾는 전역 검색 |
| 스타일 항목이 `자동` 으로 부풀려짐 | `preset: laravel` 이름만 있는데 프리셋 내용을 그 파일의 근거로 착각 |
| 반복 코드 9곳 중 6곳만 인용 | 항목을 묶으며 위치까지 줄임. 서술을 좁히면 검산이 늘 통과 |
| 근거 칸에 "notice 가 발생한다" | 실행해야 아는 것을 근거로 씀 |
| 요약이 계속 산문으로 나옴 | "설명 넣지 마라" 와 "요약에 명시해라" 가 동시에 걸려 있었음 |

**프롬프트로 막는 것보다 도구로 막는 쪽이 항상 싸다.** 다만 `Write` 를 주고 `Grep` 을
되돌리며 그 보증을 두 번 내려놓았다. 맞바꿈은 [DESIGN.md](DESIGN.md) 에 기록.

## 아직 안 된 것

| 항목 | |
|---|---|
| `docs/conventions/` | **비어 있다.** 항목 대부분이 `판단` 으로 떨어지는 원인 |
| Python / FastAPI 대상 | 설계만 |
| `migration-engineer` 이후 4 단계 | 주석 처리 — 지금은 리포트까지만 |
| 승인 관문 | `migration-engineer` 진입 직전 한 번 멈추는 형태로 정리, 미구현 |
