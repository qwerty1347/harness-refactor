### 작업-01. `approve_order` 독스트링을 파일 안에서 읽어낸 동작 서술로 교체

| | |
|---|---|
| 해소 | 없음 |
| 부분 해소 | 항목-07 — 29줄 독스트링 1곳만 교체. 모듈·데이터클래스 3개·`main` 5곳의 부재는 남긴다. 없는 자리에 새 서술을 만드는 것은 파일 안에 근거가 없는 새 문장을 쓰는 일이다 |
| 단계 | 1 (동작 무관) |
| 위험 | 낮음 |

**방법** — 29줄의 독스트링 내용(`A tangled, messy function that we'll clean up in the video.`)을 지우고, 그 자리에 31~55줄 조건식과 반환값에서 읽어낼 수 있는 동작만 한 줄 요약으로 다시 쓴다. `order` 와 `user` 의 속성으로 판정해 `"approved"` 또는 `"rejected"` 를 돌려준다는 사실까지만 쓴다. 규칙을 그렇게 정한 이유·배경·작업 메모는 쓰지 않는다. 독스트링 위치와 삼중따옴표 형식은 그대로 두고, 함수 시그니처와 본문은 건드리지 않는다.

**확인** — 29줄에 `video` · `messy` · `clean up` 같은 파일 밖 작업 메모 문구가 남아 있지 않은지 Grep 으로 확인한다. 새 독스트링이 서술한 반환값 두 가지가 실제 `return` 문 10곳의 리터럴 집합과 일치하는지 대조한다. 28줄 `def` 줄과 30줄 이후 본문이 원문과 문자 수준으로 같은지 대조한다.

### 작업-02. 판정 결과 문자열 리터럴을 모듈 상수로 올린다

| | |
|---|---|
| 해소 | 없음 |
| 부분 해소 | 항목-03 — 리터럴 흩어짐만 해소. 반환 타입 `str` 이 두 값만 유효함을 표현하지 못하는 층은 남긴다. 반환 타입 변경·열거형 도입은 시그니처가 바뀌는 4단계다 |
| 단계 | 2 (파일 안) |
| 위험 | 낮음 |

**방법** — 모듈 상단 `dataclasses` import 줄 다음, `Item` 정의 앞에 판정 결과 상수 2개를 선언한다. 값은 원문 리터럴 `"approved"` 와 `"rejected"` 를 그대로 쓰고, 이름만 붙인다. 그다음 `"approved"` 4곳(38·41·48·53줄)과 `"rejected"` 6곳(37·43·45·50·55·58줄)을 각각 상수 참조로 바꾼다. 타입 애노테이션을 붙이지 않고 새 import 도 추가하지 않는다. 16줄 주석 안의 `"bulk"` / `"normal"` 과 47줄·40줄의 비교 리터럴은 판정 결과가 아니므로 손대지 않는다.

**확인** — `"approved"` / `"rejected"` 문자열 리터럴이 상수 선언 2줄 외에는 파일에 남아 있지 않은지 Grep 으로 확인한다. 상수 참조로 바뀐 `return` 문이 정확히 10개이고 원문의 승인/거부 배치(37·43·45·50·55·58 거부, 38·41·48·53 승인)와 1:1로 대응하는지 대조한다. 조건식·분기 구조는 이 작업 전후로 문자 수준에서 같아야 한다.

### 작업-03. `approve_order` 분기를 조기 반환 가드로 평탄화

| | |
|---|---|
| 해소 | 항목-04 |
| 부분 해소 | 항목-01 — 중첩 깊이와 들여쓰기만 해소. 승인 규칙 전부가 한 함수에 있는 구조는 남긴다. 각 규칙 덩어리가 한 곳에서만 쓰여 추출 기준(두 곳 이상 반복)을 충족하지 않는다 |
| 단계 | 2 (파일 안) |
| 위험 | 중간 — 승인 판정의 모든 반환 경로를 건드린다 |

**방법** — 31~55줄에서 모든 갈래가 `return` 으로 끝나는 것을 근거로, 바깥 4개 분기(31·32·33·34줄)를 조기 반환 가드로 뒤집어 `else` 블록 7곳(39·42·44·46·49·51·54줄)을 제거한다. 바꾸는 것은 비교 방향과 `else` 배치뿐이다 — `user.is_premium` 은 부정으로, `order.amount > 1000` 은 반대 방향 비교로, `not order.has_discount` 는 긍정으로, `user.region != "EU"` 는 동등 비교로 뒤집는다. 두 조건을 하나로 합치지 않고, 새 조건·새 변수·방어 코드를 넣지 않는다. 47줄의 `and` 결합 조건, 35~37줄의 `for` 순회와 음수 가격 검사, 40줄 통화 비교, 52줄 관리자 분기는 조건식 원문 그대로 옮긴다. 30줄 `try:` 와 56~58줄 `except Exception:` 골격, 57줄 주석은 그대로 두고 그 안쪽만 평탄화한다.

**확인** — 함수 본문에 `else` 가 0건인지 Grep 으로 확인한다. `return` 문이 여전히 10개이고, 각 반환값이 원문에서 같은 조건 조합에 매달려 있던 값과 같은지 조건별로 대조한다. 평탄화 후 조건식 목록이 원문 9개 조건(31·32·33·34·36·40·47·52줄, 35줄 순회)의 부정 또는 역방향 형태로 1:1 대응하며, 병합되거나 새로 생긴 조건이 없는지 대조한다. 최대 들여쓰기가 32칸에서 줄었는지, 28줄 `def` 줄이 원문과 같은지 확인한다.
