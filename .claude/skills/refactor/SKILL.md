# 리팩토링 진단

지정한 파일을 `legacy-analyzer` 에게 분석시키고 그 리포트를 `_workspace/` 에 남긴다.

## 완료 조건

**아래 두 파일을 모두 만들어야 끝난 것이다.**

```
_workspace/00_input.md              ← 1~4 단계 (준비)
_workspace/01_legacy_analysis.md    ← 5~6 단계 (진단)
```

`00_input.md` 만 만들고 멈추지 않는다. 준비는 산출물이 아니라 중간 과정이다.
1 단계의 중단 조건(대상을 못 찾음 등)에 걸리지 않는 한, **중간에 사용자에게 되묻지 말고
6 단계까지 이어서 진행한다.**

## 읽는 파일은 이게 전부다

**대상 파일 하나를 진단하는 작업이다. 프로젝트를 훑지 않는다.**

| 주체 | 읽는 것 |
|---|---|
| 오케스트레이터 | `composer.json` (또는 `pyproject.toml`), lock 파일은 **Grep 만**, 설정 파일 존재 확인 |
| legacy-analyzer | **대상 파일**, `00_input.md`, 근거로 지정된 설정 파일 |

여기에 없는 파일은 열지 않는다. 특히:

- `composer.lock` 을 Read 하지 않는다 (8000 줄 이상 — Grep 으로 필요한 줄만)
- 대상 파일이 의존하는 다른 소스 파일을 열지 않는다
- 호출자를 찾는 프로젝트 전역 Grep 을 하지 않는다
- `vendor/` `node_modules/` `storage/` 는 어떤 이유로도 건드리지 않는다

## 코드는 고치지 않는다

이 하네스는 진단까지만 한다. 수정 담당 에이전트는 아직 없다.

사용자가 **"리팩토링해줘"** 라고 말해도 마찬가지다. 그 요청은 "무엇을 고쳐야 하는지 찾아줘" 로
해석하고 **진단을 끝까지 수행한다.** 요청과 어긋난다고 판단해 중간에 멈추지 않는다.
수정 여부는 리포트를 다 만든 뒤 사용자가 정한다.

## 1. 대상을 받는다

호출할 때 받은 인자가 분석 **대상**이다. 파일 경로일 수도, 디렉토리일 수도 있다.

- 경로가 주어졌다 → 실재하는지 확인하고 그것만 대상으로 한다
- 파일명만 주어졌다 (`OrderService.php`) → Glob 으로 찾는다.
  후보가 여러 개면 목록을 보여주고 사용자가 고르게 한다. **임의로 고르지 않는다**
- 못 찾았다 → **거기서 멈춘다.** 비슷한 이름으로 추측해서 진행하지 않는다
- 인자가 없다 → **전체를 스캔하지 말고 먼저 물어본다.**
  "어떤 파일을 볼까요?" 전체 분석은 사용자가 명시적으로 "전체" 라고 했을 때만 한다

## 2. 스택과 파일 종류를 판정한다

먼저 언어와 프레임워크를 정한다.

| 판정 | 근거 |
|---|---|
| 언어 | 대상 파일 확장자 (`.php` / `.py`) |
| 프레임워크 | `composer.json` + `artisan` / `pyproject.toml` + FastAPI import |

그다음 **파일 종류**를 본다. 종류마다 볼 것이 다르다.

| 경로 / 확장자 | 종류 | 관심사 |
|---|---|---|
| `app/Services/*.php`, `app/Models/*.php` | 순수 PHP 클래스 | 클래스 설계, 의존성, 책임 분리 |
| `app/Http/Controllers/*.php` | 컨트롤러 | 비즈니스 로직 유출, 요청 검증 위치 |
| `*.blade.php` | Blade 뷰 | 로직이 뷰에 새어들어왔는지 |
| `routes/*.php` | 라우트 정의 | 라우트 구조, 미들웨어 |
| `database/migrations/*.php` | 마이그레이션 | **대상에서 제외한다** |
| `app/routers/*.py` | FastAPI 라우터 | 핸들러 비대화, 의존성 주입 |
| `app/schemas/*.py` | Pydantic 스키마 | 검증 책임 위치 |
| `alembic/versions/*.py` | 마이그레이션 | **대상에서 제외한다** |

`.blade.php` 는 확장자가 `.php` 지만 PHP + HTML + Blade 지시문이 섞여 있다.
순수 클래스와 같은 기준으로 보지 않는다.

마이그레이션 파일이 대상으로 지정되면 **이유를 말하고 멈춘다.** 이미 실행된 이력이라 손대지 않는다.

## 3. 근거와 제약을 모은다

### 런타임 제약 — 천장을 먼저 읽는다

```json
// composer.json
"require": { "php": "^7.3", "laravel/framework": "^8.0" }
```

```toml
# pyproject.toml
requires-python = ">=3.9"
```

선언된 **하한**이 곧 상한이다. `^7.3` 은 "7.3 에서도 돌아야 한다" 는 뜻이므로,
실제 서버가 더 높더라도 보수적으로 잡는 쪽이 안전하다.

### 하한은 lock 파일로 교차 확인한다 — 단, Grep 으로만

**`composer.json` 의 선언만 믿지 않는다.** 설치된 패키지가 더 높은 버전을 요구하면
실제 하한이 올라간다. 레거시에서는 선언과 실제가 어긋나는 일이 흔하다.

```
composer.json                 php: ^7.3|^8.0     → 7.3 처럼 보이지만
elasticsearch/elasticsearch   php: ^7.4 || ^8.0  → 실제 하한은 7.4
```

**`composer.lock` 을 Read 하지 않는다.** 8000 줄이 넘어 대상 파일보다 훨씬 크다.
파일 하나 진단하는 데 그 20 배를 읽는 것은 낭비다. Grep 으로 제약 줄만 뽑는다.

```
Grep  패턴: "php":     파일: composer.lock
```

나온 값 중 **가장 높은 하한**을 확정 하한으로 삼는다.
Python 은 `uv.lock` / `poetry.lock` 에 같은 방식.

lock 파일이 없으면 선언값을 쓰되 `00_input.md` 에 **"lock 미확인"** 을 적는다.

**패키지별 표를 만들지 않는다.** `00_input.md` 에는 확정 하한 한 줄과
그 근거가 된 제약값 하나면 충분하다.

```markdown
- 확정 하한: PHP 7.4
  (composer.json 은 ^7.3|^8.0 이나, lock 에 ^7.4 || ^8.0 요구 패키지 존재)
```

### 확정된 하한 기준으로 제외 목록을 만든다

하한을 정한 뒤, **그보다 나중에 도입된 문법만** 제외한다.
하한을 낮게 잡으면 쓸 수 있는 문법을 못 쓴다고 판단하게 되므로 정확히 잡는다.

| 문법 | 도입 |
|---|---|
| arrow function `fn() =>`, typed property, `??=` | 7.4 |
| 생성자 프로퍼티 승격 `__construct(private Repo $r)` | 8.0 |
| `match` 식, nullsafe `?->`, named arguments, `str_contains()` | 8.0 |
| `enum` | 8.1 |
| `readonly` | 8.2 |

`00_input.md` 에는 **제외 목록만** 적는다. "사용 가능한 것" 과 섞어 쓰지 않는다 — 읽는 쪽이 헷갈린다.

문법뿐 아니라 프레임워크도 같다. Laravel 상한이 8 이면 9+ 전용 헬퍼·API 를 제외한다.

### 근거 — 있는 것만 모은다

우선순위대로 **실재하는 것만** 목록에 넣는다.

| 순위 | 근거 |
|---|---|
| 1 | 프로젝트 설정 파일 — `phpstan.neon`, `.editorconfig`, `pyproject.toml` |
| 2 | 컨벤션 문서 — `docs/conventions/*.md`, 프로젝트 `CLAUDE.md` |
| 4 | 언어·프레임워크 표준 — PSR-12, Laravel 관례 |

**3순위(주변 코드)는 목록에 넣지 않는다.** analyzer 는 대상 파일 하나만 읽는다.
주변 파일을 근거로 적어두면 그것들을 열러 가고, 파일 하나 보는 데 프로젝트 전체를 훑게 된다.

설정 파일을 목록에 올릴 때는 **그 파일에서 읽은 값을 그대로 옆에 적는다.**
`preset: laravel` 처럼 이름만 있고 규칙 내용이 없으면 **`(프리셋 — 세부 규칙 없음)`** 이라고 덧붙인다.
그래야 analyzer 가 프리셋 내용을 그 파일의 근거로 착각해 등급을 올리지 않는다.

```markdown
- [1순위] `.editorconfig` — 스페이스 4칸, LF, UTF-8, 파일 끝 개행
- [1순위] `.styleci.yml` — preset `laravel` **(프리셋 — 세부 규칙 없음)**, `no_unused_imports` 비활성
```

**설정 파일은 읽기만 한다. 실행하지 않는다.**
Pint / PHPStan / Ruff / mypy 를 설치하거나 실행하지 않는다. 이유는 `DESIGN.md` 에 있다.
없는 도구를 설치하려 들지 않고, 돌리지 않은 것을 돌린 척하지 않는다.

## 4. `_workspace/00_input.md` 를 쓴다

`_workspace/` 는 **지금 작업 중인 프로젝트**(현재 디렉토리) 에 만든다.

```markdown
# 분석 입력

- 대상: app/Services/OrderService.php
- 종류: 순수 PHP 클래스
- 관심사: 클래스 설계, 의존성, 책임 분리      ← 2 단계 종류별 표에서 그대로 옮긴다
- 스택: PHP / Laravel

## 런타임 제약
- 확정 하한: PHP 7.4
  (composer.json 은 ^7.3|^8.0 이나, lock 에 ^7.4 || ^8.0 요구 패키지 존재)
- laravel/framework: ^8.0
- 위 상한을 넘는 문법·API 는 제안하지 않는다

## 사용 가능한 근거
- [2순위] docs/conventions/php-laravel.md
- [4순위] PSR-12
- 1순위 설정 파일 없음

## 사용자 요청 원문
"OrderService 리팩토링해줘"
```

없는 근거는 **없다고 적는다.** 빈칸으로 두지 않는다.

## 5. legacy-analyzer 를 띄운다

`00_input.md` 를 쓴 **직후에 바로** `legacy-analyzer` 서브에이전트를 실행한다.
여기서 사용자에게 확인을 구하지 않는다.

### 넘기는 것은 이 넷뿐이다

1. 대상 파일 경로
2. 파일 종류와 관심사
3. 스택과 런타임 제약 (확정 하한)
4. `_workspace/00_input.md` 를 먼저 읽으라는 지시

### 넘기면 안 되는 것

| 금지 | 이유 |
|---|---|
| 대상 파일의 내용 | analyzer 가 직접 읽는다. 붙여넣으면 같은 것을 두 번 읽는다 |
| 미리 찾아둔 문제점·힌트 | **analyzer 가 스스로 찾아야 한다** |
| 이전 실행에서 나온 발견 항목 | 받아쓴 항목은 근거 추적이 안 된다 |
| 어디를 중점적으로 보라는 지시 | 관심사(2 번) 외에 방향을 정해주지 않는다 |

**오케스트레이터는 대상 파일을 읽지 않는다.** 읽고 분석해서 힌트로 넘기면
analyzer 의 원칙(근거 명시, What/Why 만, 등급 판정)이 적용되지 않은 항목이 리포트에 섞인다.
같은 파일을 두 번 분석하느라 시간도 두 배로 든다.

프롬프트는 짧을수록 좋다. 위 넷이면 충분하다.

analyzer 는 리포트를 `_workspace/01_legacy_analysis.md` 에 **직접 쓰고 요약만 돌려준다.**

## 6. 요약을 전달한다

**리포트 파일은 analyzer 가 이미 썼다. 다시 쓰지 않는다.**
파일이 생겼는지만 확인하고, 돌려받은 요약을 그대로 사용자에게 전달한다.

**리포트 본문을 읽지 않는다.** 확인하겠다고 Read 하면 절약한 만큼을 도로 쓴다.

돌려받는 요약은 이 셋이다.

- 발견 항목 수 (등급별로 — `자동` 몇 건, `확인 필요` 몇 건)
- 가장 무거운 항목 2~3개
- 리포트 파일 경로

**여기서 끝낸다.** 수정하지 않고, 수정 계획도 세우지 않는다.
고칠 에이전트가 아직 없으므로 "고쳐드릴까요" 라고 넘겨짚지 않는다.
수정이 필요하면 사용자가 리포트를 보고 따로 요청한다.

## 에러 핸들링

| 상황 | 처리 |
|---|---|
| 대상 파일 없음 | 멈춘다. 추측한 경로로 진행하지 않는다 |
| 후보가 여러 개 | 목록을 보여주고 고르게 한다 |
| 마이그레이션 파일이 대상 | 이유를 말하고 멈춘다 |
| `composer.json` / `pyproject.toml` 없음 | 런타임 제약을 "확인 불가" 로 적고 진행. 이 경우 **버전 관련 제안을 일절 하지 않는다** |
| 근거가 하나도 없음 | 그대로 진행하되 `00_input.md` 에 "근거 없음" 을 명시. 리포트 항목이 대부분 `판단` 등급이 될 것임을 사용자에게 알린다 |
| 리포트 파일이 생기지 않음 | analyzer 가 돌려준 사유를 그대로 전달한다. 오케스트레이터가 대신 만들지 않는다 |

## 하지 않는 것

- 코드 수정 — 이 하네스에는 수정 담당 에이전트가 없다
- 정적 분석 도구 설치·실행
- `_workspace/` 밖에 파일 쓰기
- 대상 프로젝트의 `.gitignore`, `composer.json`, `composer.lock` 수정
- 인자 없이 호출됐을 때 전체 코드베이스 스캔
